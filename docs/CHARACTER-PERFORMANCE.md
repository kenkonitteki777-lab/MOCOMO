# モコモの表現と展開の再設計

2026-10-08。ユーザーが「表情と汎用性に乏しいことが根本課題」と指摘。機能追加の前にキャラクターの表現基盤を優先する。以下は制作方針と候補であり、新造形の承認や完成を意味しない。

## 実装の診断
`Moco.tsx`は7表情と4ポーズの全身画像切替。ポーズ指定時は表情の画像より優先される。つまり飛びながら困る、歩きながら相手を見る等の組合せを自由に演じられない。既存のCSSは主に全体の移動・回転・拡縮。横／後ろ姿・顔の独立制御・連続演技・印刷向け平面マスターは未完成。

問題は表情枚数だけではない。視線、ためらい、相手を待つ間、感情の変化、動作の予備動作と余韻が不足している。モコモは安心する友達だが、悲しみ・不満・驚きも感じる存在として設計する。困る／むっとする顔も怖さを抑え、悪役化しない。

## 変えない核と、動かせる幅
核：白い雲、3つのちょこん、淡いピンクのほっぺ、小さな手足、選択済みの顔の基本比率。
幅：視線、目の開閉と形、口、手足、頭の雲の遅れと弾性、全身の軽い伸縮、前／横／後ろの姿。
衣装・模様で別物にする前に、シルエットと演技で同一性を保つ。承認済みアプリ絵を直ちに差し替えない。

制作検証：文字なし・縮小表示・白背景・暗背景で感情を見分けられるか。12枚を増やすことを目的にせず、似た顔は統合／再制作する。子どもに伝わるかは実使用で検証が必要。

## 再利用できる制作基盤
アプリ用の部品化された2D表現を最初の試験候補とする。顔、目、口、手足、頭の雲、影を分けた同じマスターから、表情×姿勢を組み合わせる。既存の柔らかな質感をどう保つかは最初の短い試作で判断し、必要なら3Dを比較する。描画方式や制作ツールはまだ確定しない。

新規ラスターパーツは画像制作ツールで参照付きに制作。既存画像を適当に分解したり、独立した生成を継ぎ足して比率を崩さない。画面幅／部品の接続／透過の縁／低性能スマホの負荷を確認する。ゲーム用の反応は動画ファイルを毎回再生するのではなく、操作に応じて組み合わせられる演技として作る。

動画は独立した鑑賞作品にも展開する。初作候補は10〜15秒「星をみつける」。気づく→近づく→雲がほどける→驚く→スイを見る→二人で喜ぶ。無音でも感情が伝わることを先に確認し、音楽と効果音を後から合わせる。動画生成／音声／書き出しは未制作。30〜60秒の物語・モコモソングの映像はその後。

## 商品化のための汎用性
- 現在の柔らかな立体表現：アプリ、絵本、アニメ。
- 同じキャラの平面版：輪郭、目と口、頭の雲だけでも識別できる設計。スタンプ、刺繍、シール、印刷で検証。
- 正面／側面／背面と寸法比率：ぬいぐるみ等の試作に使う資料。材質や縫製の実現性は別途試作が必要。

一色・24〜32px・小さな刺繍／印刷の想定で識別性を比較する。顔だけ／全身／横向きでもモコモと分かるかを確かめる。商品化しやすさはデザインだけで保証しない。

## 次の制作順
1. 感情12候補＋前／横／後ろの表現設計案を並べ、同一性と差を評価。
2. 一体のモコモで独立した顔・手足・頭の雲の演技を試作。
3. 10〜15秒の一場面で、感情の流れと動画への展開を検証。
4. 合格した基盤をホーム・スイの遊び・絵本へ反映し、仲間へ拡張。
5. 平面商品版、スタンプと短編の制作を並行。
